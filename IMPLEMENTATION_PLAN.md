## Fixed Cryptographic & Architecture Decisions (D1–D8)

All phase owners must obey these fixed rules without alteration:

- **D1 — Hybrid Encryption Standard:** AES-256-GCM encrypts the file; RSA-OAEP (SHA-256, MGF1-SHA-256) wraps the AES key for the recipient; RSA-PSS (SHA-256, salt length 32) signs the canonical package header. RSA never encrypts files directly. ECDSA is never used for encryption. No custom ciphers or hardcoded keys.
- **D2 — RSA Key Pairs:** Each user possesses one RSA-3072 key pair. X.509 `KeyUsage` = `digitalSignature` + `keyEncipherment`.
- **D3 — Private Key Protection at Rest:** User private keys are stored in the database exclusively as encrypted PKCS#8 PEM (`BestAvailableEncryption`, passphrase = user password). Passwords are stored separately as salted `scrypt` hashes via Werkzeug. Private keys are unlocked in-memory only during single requests when the user re-enters their password. Private key material is NEVER stored in sessions, logs, HTML, or API responses.
- **D4 — Mini Public Key Infrastructure (PKI):** Self-signed Root CA (RSA-4096, 10-year validity, `BasicConstraints ca=True`, `KeyUsage keyCertSign+cRLSign`). Root CA private key encrypted with passphrase from `CIPHERLOCK_CA_PASSPHRASE` env var (file mode `0600`). User certificates issued for 1 year with unique serial numbers, `CN=name`, `emailAddress=email`, SAN email, tracked in the database.
- **D5 — AES-GCM File Encryption:** Fresh 32-byte session key and random 12-byte nonce generated for every single uploaded file. Stored format = `ciphertext || 16-byte GCM tag`. Canonical header bytes passed as Additional Authenticated Data (AAD).
- **D6 — Canonical Signed Header:** JSON sorted keys, no spaces, UTF-8 encoded: `{"version": 1, "sender_id": ..., "receiver_id": ..., "original_filename": "...", "nonce_b64": "...", "wrapped_key_b64": "...", "ciphertext_sha256_hex": "...", "sender_cert_serial": ...}`. RSA-PSS signature covers this exact byte string. At verification, `ciphertext_sha256_hex` is **recomputed from the disk file**, never trusted from database fields.
- **D7 — Receiver Pipeline (Fail-Closed):** Authorization Check $\rightarrow$ X.509 Certificate Validation (CA signature, validity dates, revocation status, subject match) $\rightarrow$ RSA-PSS Signature Verification $\rightarrow$ **Only Then** RSA-OAEP Key Unwrap $\rightarrow$ AES-GCM In-Memory Decryption. If any step fails, display *"Signature verification failed. File may have been modified or sender authenticity could not be established."* and **never decrypt**.
- **D8 — File Storage Constraints:** Max 25 MB per file, `secure_filename`, stored under random UUID filename `<uuid4>.bin` in `backend/storage/encrypted/` with `0600` permissions. Plaintext is **never** written to disk.

## Global Module & API Specifications

Later phases depend on exact python function signatures and REST endpoints:

### Backend Python Modules (`backend/crypto/`)

#### 1. `crypto/aes.py`
- `generate_session_key() -> bytes` (256-bit random key)
- `encrypt_bytes(key: bytes, plaintext: bytes, aad: bytes) -> tuple[bytes, bytes]` (returns `(nonce, ciphertext_with_tag)`)
- `decrypt_bytes(key: bytes, nonce: bytes, data: bytes, aad: bytes) -> bytes` (raises `DecryptionError` on GCM tag mismatch)

#### 2. `crypto/rsa.py`
- `generate_rsa_keypair(bits: int = 3072, public_exponent: int = 65537)`
- `private_key_to_encrypted_pem(priv, passphrase: str) -> bytes`
- `load_private_key(pem: bytes, passphrase: str)`
- `public_key_to_pem(pub) -> bytes`
- `load_public_key(pem: bytes)`
- `public_key_fingerprint(pub) -> str` (SHA-256 hex string of DER SubjectPublicKeyInfo)
- `wrap_session_key(public_key, session_key: bytes) -> bytes` (RSA-OAEP SHA-256, MGF1-SHA-256)
- `unwrap_session_key(private_key, wrapped: bytes) -> bytes` (raises `UnwrapError`)

#### 3. `crypto/signatures.py`
- `sign_data(private_key, data: bytes) -> bytes` (RSA-PSS SHA-256, salt length 32)
- `verify_signature(public_key, data: bytes, signature: bytes) -> bool` (catches `InvalidSignature`, returns bool)
- `sha256_hex(data: bytes) -> str`

#### 4. `crypto/ca.py`
- `init_ca()` (creates RSA-4096 Root CA, encrypted with `CIPHERLOCK_CA_PASSPHRASE`, mode `0600`)
- `load_ca()`
- `issue_user_certificate(name: str, email: str, public_key) -> tuple[bytes, int]` (returns `(cert_pem, serial)`)
- `revoke_certificate(serial: int)`

#### 5. `crypto/certificates.py`
- `load_certificate(pem: bytes)`
- `verify_certificate(cert_pem: bytes, expected_email: str = None) -> CertReport`
  - `CertReport` dataclass fields: `ca_signature_ok: bool`, `validity_ok: bool`, `not_revoked: bool`, `subject_ok: bool`, `key_usage_ok: bool`, `valid: bool`, `reason: str`

#### 6. `crypto/package.py`
- `canonical_header(version, sender_id, receiver_id, original_filename, nonce_b64, wrapped_key_b64, ciphertext_sha256_hex, sender_cert_serial) -> bytes`
- `build_package(plaintext: bytes, original_filename: str, sender_id: int, receiver_id: int, sender_private_key, sender_cert_pem: bytes, receiver_public_key) -> dict`
- `verify_package(package: dict, expected_sender_email: str = None) -> SecurityReport`
  - `SecurityReport` dataclass fields: `certificate: str` ("VALID"/"INVALID"), `signature: str` ("VALID"/"INVALID"), `integrity: str` ("PASSED"/"FAILED"), `overall: str` ("TRUSTED"/"POSSIBLE TAMPERING"/"UNTRUSTED SENDER"), `messages: list[str]`
- `open_package(package: dict, receiver_private_key) -> bytes` (raises `TamperError` if `overall != "TRUSTED"`)
- `format_security_box(report: SecurityReport) -> str`

### Database Schema (SQLite 3 — `backend/database/cipherlock.db`)

1. **`users`**: `id` (INTEGER PK AUTOINCREMENT), `name` (TEXT), `email` (TEXT UNIQUE), `password_hash` (TEXT), `public_key` (TEXT PEM), `encrypted_private_key` (TEXT PEM), `certificate` (TEXT PEM), `is_admin` (INTEGER), `is_active` (INTEGER), `created_at` (TIMESTAMP).
2. **`files`**: `id` (INTEGER PK AUTOINCREMENT), `sender_id` (INTEGER FK users), `receiver_id` (INTEGER FK users), `original_filename` (TEXT), `encrypted_filename` (TEXT UUID), `encrypted_session_key` (TEXT B64), `nonce` (TEXT B64), `signature` (TEXT B64), `sender_certificate` (TEXT PEM), `ciphertext_sha256` (TEXT HEX), `status` (TEXT), `created_at` (TIMESTAMP).
3. **`certificates`**: `id` (INTEGER PK AUTOINCREMENT), `user_id` (INTEGER FK users), `certificate` (TEXT PEM), `serial_number` (INTEGER UNIQUE), `issued_at` (TIMESTAMP), `expires_at` (TIMESTAMP), `status` (TEXT active/revoked/expired).
4. **`activity_log`**: `id` (INTEGER PK AUTOINCREMENT), `user_id` (INTEGER FK users), `action` (TEXT), `detail` (TEXT), `created_at` (TIMESTAMP).
